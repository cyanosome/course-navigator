### v1（2026-11-03）

- 2026-11-03 のデザインシステム・コンペで、3つの応募作（alpha・beta・gamma）から土台に選んだ **案 alpha** を元にした確定版。コンペの目的・条件・審査・結果・生データの場所は実験報告 [`docs/experiments/2026-11-03_frontend-design-competition.md`](../experiments/2026-11-03_frontend-design-competition.md) にある。
- 事前登録した判定規則は「必須 DM1〜DM5 を満たす案のうち、K1・K2・K3 の順位の合計が最小の案」。必須 DM4（フォントと色のすべての決定に理由と検証がある）は、文言どおりの読み（理由に仕様の節番号が要る）で3案とも満たさなかった。alpha の欠けは色の3件（line-ui・rule・focus）、beta は12件、gamma は節番号の欠け3件と中身の対応しない節番号1件と検証の結果の欠け5件。
- 全案が必須を満たさない場合の規則は、事前登録に無かった。そこで**事前登録に無い決め方**として、DM4 の欠けが最も少なく、順位の合計も最小（alpha 4・beta 6・gamma 8）なのがどちらも alpha であることから、alpha を土台にし、確定版で欠けを埋めた〔D1〕。順位の内訳: K1（要注意の件数）は3案とも 0。K2（最初の表示のフォント）は alpha 67,784 B・beta 71,176 B・gamma 4,441,408 B。K3（盲検2人の平均順位）は alpha 1.17・beta 1.83・gamma 3.00。
- 他の応募作（beta・gamma）の要素は、alpha について審査で見つかった問題を解消する場合に限って取り込み、出どころ（ファイル:行）を変更履歴に書いた。他の案に解消の要素が無い問題には最小の修正を入れ、「審査後の修正（応募作に無い）」と書いた。
- 変更履歴のファイル:行は、コンペの作業フォルダ `frontend/design/` からの相対パス（`entries/beta/specimen.html:331` は beta の見本の331行目、`judging/k3-j1.md:51` は審査役 J1 の記録の51行目）。審査役 J1・J2 の盲検では、案2 が alpha、案3 が beta、案1 が gamma。
- 見本（`specimen.html`）・スクリーンショット・検証の出力（`checks.txt`）・スクリプトはリポに入れていない。確定版のものは作業フォルダの `frontend/design/final/` にある（以下 `final/`）。置き場所は実験報告の「生データの場所」を見る。配信するフォントだけ `frontend/public/fonts/` に置いた。

## 1. デザインの原則

仕様とペルソナとオーナーの指示から5つを決めた。見た目の判断で迷ったら、この順に優先する。

1. **開いた瞬間に、曜限・単位・科目名・授業でやることが読める。** 1年生は通学中に数分ずつ使い、長い文は読まない（仕様 1.1 ペルソナ A）。最初の提案は操作0回で見えていること（要点1、3.1）。時間割を組むときに見る順（いつ・何単位・何をやる）に合わせ、一覧の行は左に曜限と単位、右に科目名と授業でやることを置く（指示 F9。`entries/e1/redesign.md` 0章）。見出しと説明文は置かない（指示 F1・F2、仕様 V2-05）。
2. **強調は濃淡と大きさだけ。太字と箱を使わない。** 文字は墨と灰の2色、16px と 14px の2サイズで階層を作る（指示 F3）〔DV2-01・DV2-02〕。カードの箱・地・影をやめ、行の間の細い線で区切る〔DV2-05〕。
3. **色は意味にだけ使う。根拠は灰の文字にする。** 色を持つのは「選んだもの・候補に入ったもの＝緑」「重なり・エラー＝赤」「フォーカス＝青」と、時間割の必修の地（灰）だけ。根拠と出典は灰の文字で、色の地も枠も付けない（指示 F8、仕様 V2-03）〔DV2-04〕。色だけで意味を伝えない（requirements.md R6-3、WCAG 1.4.1）。重なりは赤に加えて三角の印と「◯◯と重なる」の文字、選んだものは緑に加えてチェックの印で示す。
4. **見たいときだけ見る。入れたことは一瞬で知らせる。** 詳細の補足（取る順・授業計画・成績のつけ方）と一覧の残りの科目は畳み、開けたときだけ出す（追加の指示、仕様 V2-11）。候補に入れたら、時間割のどこに入ったかを一瞬だけ見せ、自分で消える（指示 F6、仕様 V2-16）〔DV2-09・DV2-13〕。動かすのは状態が変わったときだけで、`prefers-reduced-motion: reduce` では動かさずに状態だけを伝える（requirements.md R6-7）。
5. **小さく、軽く。** 部品の種類と色の数を増やさない。書体は1つの太さだけを配り（2.4）、スマホの回線で最初の提案を待たせない（3.4 の段0〜2「待ち なし」、11.2「最初の提案までの時間 2秒以内」、requirements.md R1-9）。

## 2. タイポグラフィ

### 2.1 書体: M PLUS 1p の 400 だけ（和文・欧文・数字とも）〔DV2-01〕

```css
--font: "M PLUS 1p", "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Meiryo", sans-serif;
/* 見出し・表の見出し・dt・b・strong の既定の太字を戻す（entries/e1/specimen.html:62） */
h1, h2, h3, th, dt, b, strong { font-weight: 400; }
```

- 本文も見出しもボタンも、この1書体の標準の太さ（400）だけで組む。太字（700）は1か所も使わず、太字のファイルを読み込まない。階層は大きさ（16px・14px と例外）と色（墨・灰）と余白で作る（指示 F3）。
- 書体の選択は v1 のまま（2.2 の比較）。欧文書体を混ぜない理由も v1 のまま。科目名は「物理化学I」「微分積分I」のように半角の I でローマ数字を書き、すぐ隣に「月2」「2単位」の数字が並ぶ（仕様 W1）。同じ書体の欧文なら、和文と高さと間隔がそろう。
- 検証: E1 の見本の6画面で、読まれた書体は M PLUS 1p 400 だけ（`entries/e1/checks.txt` 4節）。W1 の太さ 600 以上の字は 0（改訂前 105。記録の `measure/README.md`・`measure/judging-machine.md`）。

### 2.2 書体を選んだ比較（v1 の事前登録の手順。v2 でも書体の選択の根拠）

v1 で M PLUS 1p を選んだ比較。v2 は太さを 400 だけにしたが、書体は変えていないので、この比較が書体の根拠として残る。門の「本物の太字のファイルがある」は v2 では要らなくなったが、4つの候補の順位には影響しない（M1〜M4 は太さによらない指標か、標準と太字の合計）。

- 位置づけ: 2026-11-03 のコンペ用の予備の比較（本実験ではない）。字の描画はブラウザでなく FreeType（Pillow）で、14px・16px を1倍の画素で描いた。
- 問い: 1年生がスマホで初めて見る科目名（カタカナの専門語と、ローマ数字の I・数字の 1 が並ぶ）を、いちばん取り違えにくく、いちばん軽く配れる和文書体はどれか。
- 門（測る前に決めた）: 禁止リストの書体でない／JIS 第1水準・ひらがな・カタカナ 100%／OFL かつ埋め込み可／本物の太字のファイルがある。
- 候補: Google Fonts の公式配布元（github.com/google/fonts）から取った、禁止・要注意に当たらないゴシック4つ。BIZ UDPGothic、M PLUS 1p、Zen Maru Gothic、Murecho。
- 指標（式は `final/verify/glyph_distinct.py` の冒頭）:
  - M1 濁点・半濁点の見分け: 「パ/バ」「ペ/ベ」「プ/ブ」「ぱ/ば」を 14px・1倍で同じ原点に描き、差 D = Σ|a−b| ÷ (Σa + Σb) の最小値。0 は同じ絵。大きいほど見分けやすい。理由: 科目名がカタカナの専門語だらけで（ユニットオペレーション、プロセス、プラント）、語を知らない1年生は文脈で補えない（仕様 1.1、3.2 原則2）。
  - M2 I・l・1・O・0 の見分け: 「I/l」「I/1」「l/1」「O/0」で同じ式の最小値。
  - M3 最初の表示の重さ: 仕様の W1・W3・W11 のワイヤーフレームの 377 字で標準と太字をサブセットした WOFF2 の合計。
  - M4 JIS 第2水準の収録率（教員名・科目名の異体字）。
- 決め方: M1〜M4 の順位の合計が最小の書体。同点なら M1。
- 仮説（事前）: BIZ UDPGothic が M1・M2・M4 で1位、M3 で最下位。

| 書体 | 門 | M1 濁点の差 | M2 欧文の差 | M3 WOFF2 合計 | M4 第2水準 | 順位の合計 |
| --- | --- | --- | --- | --- | --- | --- |
| M PLUS 1p | 通る | 0.080（1位） | 0.071（2位） | 73,652 B（1位） | 61.09%（3位） | **7** |

- 結果: 規則どおり M PLUS 1p を採った。仮説は M1 で外れた（BIZ UDPGothic は「ぱ/ば」が 0.053 で、M PLUS 1p の 0.080 より取り違えやすい）。補足で 28px・42px（スマホの2倍・3倍に当たる）でも測ったが、M1 の最小値は M PLUS 1p 0.097 / BIZ UDPGothic 0.047 / Zen Maru Gothic 0.034〜0.049 で、順は変わらなかった。
- 弱点（採用しても残る）: M PLUS 1p は小文字の l と大文字の I がほぼ同じ形（D = 0.071）。画面の文言と科目名に小文字の l はほぼ出ないので、I と数字の 1（D = 0.856）、O と 0（D = 0.481）の見分けを優先した。第2水準は 61% なので、欠けた字は 2.5 の代わりの書体で出る。
- 生データ: `final/verify/glyph_distinct.out.txt`（v1 のコンペの作業フォルダ。M3 は WOFF2 の圧縮で実行ごとに数十バイト揺れる。1回目は 73,676 / 172,024 / 132,516 B で、順位は同じ）。再現: `uv run --with fonttools --with brotli --with pillow python -I verify/glyph_distinct.py <ux-spec.md> "名前=標準.ttf,太字.ttf" …`

### 2.4 配信（400 の2ファイル）〔DV2-01〕

| ファイル（`frontend/public/fonts/`） | 中身 | 大きさ | 最初の表示で読むか |
| --- | --- | --- | --- |
| `mplus1p-400-ui.woff2` | 標準の太さで画面に出る字 432 字＋ASCII（v1 の見本の字から作った仮のもの。下の 2.4.1 で作り直す） | 40,628 B | 読む |
| `mplus1p-400-rest.woff2` | 元の書体の全部の字 8,331 字（第1水準 100%） | 661,676 B | 読まない（unicode-range の外の字が出たときだけ） |
| `OFL.txt` | SIL Open Font License 1.1（M+ の著作権表示つき） | 4,389 B | ─ |
| `mplus1p-700-ui.woff2`・`mplus1p-700-rest.woff2` | v1 の太字 | 27,536 B・705,360 B | v2 では読まない。@font-face に書かない。ファイルを消すかは実装の作業で決める |

```css
/* ui と rest の2つ。ファイル名は frontend/public/fonts/ のものと同じ */
@font-face {
  font-family: "M PLUS 1p";
  src: url("/fonts/mplus1p-400-ui.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
  unicode-range: /* ui に入れた字（ビルドで書き出す） */;
}
@font-face {
  font-family: "M PLUS 1p";
  src: url("/fonts/mplus1p-400-rest.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
  unicode-range: /* 書体の全部の字から ui の字を除いた範囲（ビルドで書き出す） */;
}
```

- ui と rest の unicode-range は重ならない。画面の字が ui に全部入っていれば rest は読まれない。
- 太さを 400 だけにしたので、v1 で最初の表示に読んでいた 700 の ui（27,536 B）が要らなくなる。今の ui のファイルでの最初の表示は 40,628 B の見込みだが、今の ui は v1 の見本の字から作ったもので、v2 の画面の字（「興味関心」「時間割」など）が全部入っているかは確かめていない。E1 の見本は rest の全部の字のファイル（661,676 B）を1つ読んでいて、ui を使っていない（`entries/e1/redesign.md` 14章）。実装の W1（375×812）では、400 の ui と rest の2つの面がどちらも読まれた（measure.py の読み込みの記録）。今の ui に W1 の字が全部入っていないためと見られる（推定）。読まれたバイト数は測っていない（8章の限界）〔DV2-18〕。
- ヒンティングと縦書きの表を外した（v1 のまま。横書きの UI だけで使い、重さを減らす。仕様 1.2「スマホ中心」、11.2「最初の提案までの時間 2秒以内」）。name テーブルは残し、ライセンスの記載が配信ファイルにも入っている。
- `font-display: swap`。書体の読み込みを待たずに代わりの書体で文字を出し、届いたら差し替える。最初の提案を文字のない状態で待たせない（要点1、11.2）。

#### 2.4.1 本番での ui の作り直し

`frontend/public/fonts/` の ui は、v1 のコンペの見本（`final/specimen.html`）に出てくる字から作った。アプリの画面の字とは違うので、実装のときに次の方針で作り直す（v1 の D4 の方針から、太さを 400 だけにした）。

- **ui に入れるのは UI の固定の文言の字と ASCII だけ。** 固定の文言は、ボタン・見出し語・ラベル・注意書き・案内の文のように、コードに書いてあって利用者やデータで変わらない文（仕様 6.2 の W1〜W13 の文言）。v2 は 400 だけなので、太さで分けない。
- **科目名・まとまりの名前・教員名・授業でやること・シラバスの文・AI の回答・入力した文のような、データで変わる字は ui に入れない。** これらは rest が unicode-range（書体の全部の字から ui を除いた範囲）で受け持つ。学科データの同梱は未決 U2 で、D（実行時に取る）になればビルドの時点で科目名が無いので、ui をデータに依存させない。
- **作り方:** 固定の文言をソースから集め、fontTools の subset で WOFF2 を作り、@font-face の unicode-range を書き出す。設定は v1 の `final/verify/build_fonts.py` と同じ（ヒンティングと縦書きの表を外す、name テーブルを残す、レイアウトの機能は ccmp・locl・liga・kern・mark・mkmk）。固定の文言を変えたら作り直す。固定の文言の字が ui に全部入っているかを、ビルドかテストで確かめる。
- **残る問題（実装のときに測る）:** W1 は最初の表示に科目名と授業でやることを出すので、その字が ui に無いと、最初の表示で rest を読む。rest が1ファイルのままだと 646 KB になる。本番では rest を unicode-range で数十に分け（Google Fonts の配信と同じ考え方）、出た字の分だけ読まれるようにする。分け方と最初の表示で読まれる量は、実データの画面で測って記録する。

### 2.5 代わりの書体

`"M PLUS 1p", "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Meiryo", sans-serif` の順（v1 のまま）。M PLUS 1p に無い字（第2水準の 39%、教員名の異体字「髙」「邉」など）は、iPhone ではヒラギノ角ゴ、Windows では游ゴシック UI かメイリオ、Android では端末のゴシックで出る。どれもゴシックなので、科目名や教員名の1字だけ形が変わっても、書体の種類（ゴシックと明朝）は混ざらない（仕様 W3 の担当）。見本の確認は v1 の `final/shots/mplus1p-400-375.png` の「齋藤・髙橋・渡邉」。

### 3.3 フォーカス・重なり・エラー・調査モードの帯・待ち

## 4. 余白・角丸・線・影・動き

- **余白**〔DV2-07〕: 8px を単位に **8・16・24・32・40・48px の6段**（指示 F4）。4 の倍数で 8 の倍数でない値は、次の2か所だけ。

| 場所 | 値 | やむを得ない理由（`entries/e1/redesign.md` 9章） |
| --- | --- | --- |
| 興味関心のチップの左右の内側（トークン `chip-pad-x`） | 12px | 16px にすると、375px の幅（使える 343px）でチップ5つが3行に折り返し、科目の1行目が 48px 下がる。12px なら2行（1行目 336px、2行目 238px）に収まる。8px では文字が輪に近すぎて押せる形に見えない |
| 知らせの小さな時間割のマスの間（トークン `mini-gap`） | 4px | マスが 16×12px と小さく、8px あけるとマスより隙間が目立って表に見えない。知らせの幅の中で5日×5限を描くための値 |

  - 余白でない値（判定の外）: 時間割の表のマスの間 `border-spacing` 4px（375px で5日の列を 59px 確保するため）、フォーカスの輪の離れ 2px、下線の離れ 3px、角丸（下）。
  - 画面の左右: スマホ 16px、PC の一覧 24px、PC の詳細 40px（上 24px・下 48px）、PC の時間割 24px。
  - 押せる大きさ: 一覧の＋は 44×44px、チップと印のボタンは高さ 40px、開閉の行・メニューの行・入力欄（スマホ）は 48px、取る順の行と［外す］は 40px（WCAG 2.5.8 の 24px を上回る）。隣り合う押せる部分は 8px 以上あける（仕様 5.2、C05）。チップの間は 8px。
  - 検証: 記録の `measure/judging-machine.md` の RM6。6画面の見えている全要素の margin・padding・row-gap・column-gap（0 を除く）で、4 の倍数 100%・8 の倍数 92.7%（値 438 個。基準は 95% 以上と 75% 以上）。W1 だけでは 100% / 84.1%（値 63 個）。8 の倍数でない値は上の2か所だけ。改訂前の W1 は 4 の倍数 92.4%・8 の倍数 32.8%。
- **角丸**〔DV2-08〕: 2px（知らせの小さな時間割のマス、凡例の色見本）、4px（時間割のマス）、8px（＋ボタン・印のボタン・主ボタン・入力欄）、12px（メニュー、知らせ）、999px（チップ）。チップだけ丸い端にして、「選ぶもの（興味関心）」と「実行するもの（ボタン）」を形で分ける（v1 と同じ考え）。
- **線**〔DV2-05〕: 区切りは rule の 1px の線だけ（行の間、開閉の行の間、上の帯の下、下のタブの上、PC の列の間）。箱（枠と地を持つ入れ物）は作らない。入れ物に見えるのは、メニュー（rule の枠）と知らせ（暗い地）の2つで、どちらも一時的に重なって出る物。
- **影**: 使わない（v1 と同じ）。重なりは線と地の明るさで示す。見本の `box-shadow: inset` は輪と枠を描くためのもので、影ではない（E1 の見本にかけた check_banlist で禁止 0・要注意 0。`entries/e1/checks.txt` 1節）。
- **動き**〔DV2-09〕: 動かすのは次の5つだけ。位置は動かさない（ずらして出す・拡大する動きは無い。知らせの `translateX(-50%)` は中央に置くためのもので、動かさない）。イージングはすべて cubic-bezier(0.2, 0, 0, 1) で、行き過ぎて戻る動きは使わない。

| 対象 | 動き | 時間 | `prefers-reduced-motion: reduce` |
| --- | --- | --- | --- |
| 知らせの出入り | 不透明度 0→1 で出る、1→0 で消える | 出る 160ms、消える 240ms。出てから 2.4 秒で消し始める | 動かさずに出し、4 秒出して消す |
| 知らせの小さな時間割のいま入れたマス | 地の塗り（透明→toast-new） | 320ms、120ms 遅れて始める（どこに入ったかに目が行くように） | 動かさず、最初から塗る |
| 開閉（詳細の補足、「ほかに N 科目」） | 印が 180° 回る、中身が不透明度 0→1 | 200ms | 止める（すぐ開く） |
| ＋ボタンと詳細の［候補に入れる］ | 輪と色の切り替え | 120ms | 0ms |
| 待ちの印（v1 のまま） | 四角3つが順に塗られる | 1.2 秒で一巡 | 止めて塗った状態（経過の数字は変わり続ける。動きではなく情報なので） |
