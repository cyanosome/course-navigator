## 1. デザインの原則

仕様とペルソナから5つを決めた。見た目の判断で迷ったら、この順に優先する。

1. **開いた瞬間に読める。** 1年生は通学中に数分ずつ使い、長い文は読まない（仕様 1.1 ペルソナ A）。最初の提案は操作0回で見えていること（要点1、3.1）。そこで、375×812 で提案カードの1件目が全体まで、高さ 667px の端末でも科目名と「なぜ」の1行目が見えることを、書体の大きさと余白の上限にする（5.2「375px での配置」）。
2. **根拠の種類は、色・形・文字の3つで見分ける。** 系統図・シラバス・AI の判断は確かさが違い、それを見分けられることが信頼の合わせ方そのもの（7.2、7.4）。色だけで意味を伝えない（requirements.md R6-3、WCAG 1.4.1）。だから3種類は、色が見えなくても、印の形と文字のラベルで分かるようにする。
3. **色は意味にだけ使う。押せるものは形で示す。** 飾りを使わない（5.6）。色を持つのは「系統図＝緑」「AI＝黄（AI の判断・待ち・AI を通る入口）」「エラー＝赤」「フォーカス＝青」の4つだけで、ボタンは墨（ink）の枠か塗り。提案カードの主の操作は[理由と出典]で、墨の塗りにする。[候補に入れる]は枠のボタンにする〔F1〕。仕様の S1 で W1 の操作は[理由と出典]（4章 S1 の #1）で、いちばん見たい指標は「理由を確かめてから候補に入れた参加者の割合」（11.1）。既定の3件は学科の全員に同じものが出るので（3.6）、[候補に入れる]を主にすると既定値の効果（3.2 原則1）を強め、既定依存率（11.2）を上げる。候補へ誘導しない（3.5「操作的な誘導は使わない」）。
4. **待ちは見えるが、急かさない。** 自由記述は 30 秒〜1分半かかる（3.4、W5-2）。待ちの1行は、どの画面でも同じ場所に同じ形で出し、経過の数字が1秒ごとに揺れないようにする（C08、requirements.md R1-1）。進み具合の割合は出せないので、割合に見える棒は描かない。
5. **小さく、軽く。** 提案は3件まで・カードの文は「なぜ」1行まで（3.2 原則3）と同じ考えで、部品の種類と色の数を増やさない。最初の画面に要るフォントは 66.6 KB（2章の実測）にとどめ、スマホの回線で最初の提案を待たせない（3.4 の段0〜2「待ち なし」、11.2「最初の提案までの時間 2秒以内」、requirements.md R1-9）。

### 2.2 書体を選んだ比較（事前登録の手順）

- 位置づけ: このコンペ用の予備の比較（本実験ではない）。2026-11-03。字の描画はブラウザでなく FreeType（Pillow）で、14px・16px を1倍の画素で描いた。
- 問い: 1年生がスマホで初めて見る科目名（カタカナの専門語と、ローマ数字の I・数字の 1 が並ぶ）を、いちばん取り違えにくく、いちばん軽く配れる和文書体はどれか。
- 門（測る前に決めた）: 禁止リストの書体でない／JIS 第1水準・ひらがな・カタカナ 100%／OFL かつ埋め込み可／本物の太字のファイルがある。
- 候補: Google Fonts の公式配布元（github.com/google/fonts）から取った、禁止・要注意に当たらないゴシック4つ。BIZ UDPGothic、M PLUS 1p、Zen Maru Gothic、Murecho。
- 指標（式は `final/verify/glyph_distinct.py` の冒頭）:
  - M1 濁点・半濁点の見分け: 「パ/バ」「ペ/ベ」「プ/ブ」「ぱ/ば」を 14px・1倍で同じ原点に描き、差 D = Σ|a−b| ÷ (Σa + Σb) の最小値。0 は同じ絵。大きいほど見分けやすい。理由: 科目名がカタカナの専門語だらけで（ユニットオペレーション、プロセス、プラント）、語を知らない1年生は文脈で補えない（1.1、3.2 原則2）。
  - M2 I・l・1・O・0 の見分け: 「I/l」「I/1」「l/1」「O/0」で同じ式の最小値。
  - M3 最初の表示の重さ: 仕様の W1・W3・W11 のワイヤーフレームの 377 字で標準と太字をサブセットした WOFF2 の合計。
  - M4 JIS 第2水準の収録率（教員名・科目名の異体字）。
- 決め方: M1〜M4 の順位の合計が最小の書体。同点なら M1。
- 仮説（事前）: BIZ UDPGothic が M1・M2・M4 で1位、M3 で最下位。

- ui と rest の unicode-range は重ならない。画面の字が ui に全部入っていれば rest は読まれない。範囲の実際の値は `final/specimen.html` の `/* font-face:start */` から `/* font-face:end */` の間にある（rest の範囲は太さごとに約 36 KB の文字列なので、本番では CSS ファイルに分けて HTML と別にキャッシュさせる）。

#### 2.4.1 本番での ui の作り直し〔D4〕

`frontend/public/fonts/` の ui の2ファイルは、コンペの見本（`final/specimen.html`）に出てくる字から作った。アプリの画面の字とは違うので、実装のときに次の方針で作り直す。

- **ui に入れるのは UI の固定の文言の字と ASCII だけ。** 固定の文言は、ボタン・見出し・ラベル・注意書き・案内の文のように、コードに書いてあって利用者やデータで変わらない文（仕様 6.2 の W1〜W13 の文言）。太さごとに「その太さで描く文言」の字を分ける（ボタンと見出しは 700、本文と補足は 400）。
- **科目名・枠の名前・教員名・シラバスの抜粋・AI の回答・入力した文のような、データで変わる字は ui に入れない。** これらは rest が unicode-range（書体の全部の字から ui を除いた範囲）で受け持つ。ブラウザは、画面に出た字が rest の範囲にあるときだけ rest を読む。学科データの同梱は未決 U2 で、D（実行時に取る）になればビルドの時点で科目名が無いので、ui をデータに依存させない。
- **作り方:** 固定の文言をソースから集め（文言を1か所にまとめるか、ビルドで文字列を集める）、fontTools の subset で太さごとに WOFF2 を作り、@font-face の unicode-range を書き出す。設定は見本の `final/verify/build_fonts.py` と同じ（ヒンティングと縦書きの表を外す、name テーブルを残す、レイアウトの機能は ccmp・locl・liga・kern・mark・mkmk）。固定の文言を変えたら作り直す。固定の文言の字が ui に全部入っているかを、ビルドかテストで確かめる。
- **残る問題（実装のときに測る）:** W1 の提案カードは最初の表示に科目名を出すので、科目名に ui に無い字があると、最初の表示で rest を読む。rest が1ファイルのままだと標準だけで 646 KB になる。本番では rest を unicode-range で数十に分け（Google Fonts の配信と同じ考え方）、科目名の字の分だけ読まれるようにする。分け方と最初の表示で読まれる量は、実データの画面で測って記録する。

### 2.5 代わりの書体

`"M PLUS 1p", "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Meiryo", sans-serif` の順。M PLUS 1p に無い字（第2水準の 39%、教員名の異体字「髙」「邉」など）は、iPhone ではヒラギノ角ゴ、Windows では游ゴシック UI かメイリオ、Android では端末のゴシックで出る。どれもゴシックなので、科目名や教員名の1字だけ形が変わっても、書体の種類（ゴシックと明朝）は混ざらない（W3 の担当の欄）。見本の確認: `final/shots/mplus1p-400-375.png` の「齋藤・髙橋・渡邉」が欠けずに出ている。

| 根拠: 履修系統図 | 緑（route）の文字と枠、薄い緑の地 | 実線。印は「四角2つを線で結んだ形」（枠と枠を結ぶ線、7.6） | 「根拠: 履修系統図」 | 提案カード、W3 のなぜ、系統図での位置 |
| シラバスより | 色なし（墨の文字・墨の細い枠） | 引用の枠の左上と右下にカギカッコの形の角（「」の形）。印は「紙」 | 見出し「シラバスより（2026年度）」とラベル「原文の引用」 | W3 の授業計画・概要の抜粋 |
| 根拠: AIがシラバスから判断 | 黄（ai）の地、墨の文字 | 破線。カードの縁も破線、印は点線の丸 | 「根拠: AIがシラバスから判断」と「間違うことがあります」 | 自由記述の結果のカード、W3 の AI の説明 |

- 緑の理由: 系統図は「取る順」と「つながる先」を示す。安全色の決まり（JIS Z 9103）で緑は「安全・進行」に使われ、1年生が日常の掲示で見慣れた意味と合う。方向のチップの選択中も同じ緑にした。方向は系統図の3年の枠から作るので（3.8）、「緑＝系統図から来たもの」がチップと根拠でそろう。
- 黄の理由: AI の判断は「間違うことがある、と毎回書く」もの（7.2）。黄は同じ決まりで「注意」に使われる。待ちの1行も AI の処理なので同じ黄の系統にした。AI を通る入口の[自分の言葉で探す]（W8 の「どこにAIを使っているか」で、AI が回答と理由を作ると書いている入口）にも、同じ黄のラベルを付けた〔F4〕。黄の地は墨の文字と組み、黄の文字は使わない（白地の黄の文字はコントラストが取れない）。
- シラバスを無彩色にした理由: 原文をそのまま引くもので、システムの判断が入らない（7.2「原文の通り」）。日本語の引用の記号「」の形で囲み、色ではなく引用であることで示す。
- 色覚の確認: 3つは形（実線と四角の印・カギの角・破線と点線の丸）と文字が違うので、色を全部取っても見分けられる（グレースケールの比較は限界に書いた）。

### 3.3 調査モードの帯・フォーカス・エラー・待ち

- **調査モードの帯**: 墨（ink）の地に紙（paper）の文字。見出しの上に全幅で出し、[使い終わった]を帯の右端に置く（8.1、C20）。墨の全幅の帯は通常のモードに一度も出ない形なので、研究者も参加者も「いま調査中」とすぐ分かる。色は足していない。
- **フォーカス**: 青（focus）の 3px の輪を 2px 離し、その間を紙の色の 2px の輪で埋める（2色の輪。WCAG の技法 C40）。PC はキーボードで入力して使い（5.3「PC はキーボード入力が楽」）、送信も Enter の扱いを決めている（W5-1）ので、キーボードの位置がどの地の上でも見える必要がある（requirements.md R6-5）。墨の帯や墨のボタンの上では、青と墨の比が 2.56:1 しかないが、内側の紙の輪と墨が 15.33:1 になる。青はフォーカスにしか使わないので、「青い輪＝いまキーボードがここ」と覚えられる。表示に動きは付けない。
- **エラー**: 赤（error）は印と見出し語（「データがありません:」など）と入力欄の枠だけ。文は墨。範囲外の言葉でも送信は止めない（C09）ので、赤い全面の警告にはせず、1行の案内にする。エラーの1行は error-tint の地＋赤の実線＋三角の印。
- **待ち**: ai-tint の地、上下に墨の破線、四角3つが順に塗られる印、「回答を作っています 0:24 [やめる]」。届いたら紙の地と墨の実線の「回答が届きました [見る]」に変える（C08）。読み上げは状態が変わったときだけで、経過の数字は読み上げない（requirements.md R6-2）。

### 3.5 禁止の色からの距離

`check_banlist.py` は色の禁止 0 件。加えて、各トークンと一番近い禁止の見本との色差 ΔE00 を出した（`final/verify/color_margin.out.md`）。paper（3.50）と paper-sunk（4.13）はクリーム系（C02）の見本としきい値 5.0 より近いが、色相が 229°・240°（寒色）で C02 の色相の門（60〜115°）を通らないので当たらない。紙と地をわずかに青みに寄せたのは、この取り違えを避けるため。ink は暖色のほぼ黒（C06）と ΔE00 6.35 で、門も通らない。そのほかは最も近いもので 7.91 以上離れている。

## 4. 余白・角丸・影・動き

- **余白**: 4px を単位に 4・8・12・16・24・32・48px の7段。画面の左右は 16px（スマホ）・24px（PC の一覧）・32px（PC の詳細）。押せる部分はスマホで高さ 44px 以上、PC で 32px 以上（WCAG 2.5.8 の 24px を上回る）、隣り合う押せる部分は 8px 以上あける（5.2、C05）。カードの中の[理由と出典]と[候補に入れる]は左右の端に離す（W2 の注）。方向のチップと[自分の言葉で探す]の間は 16px〔F4〕。段の外の値は1つだけで、方向のチップの左右の内側 11px（トークン `--chip-pad-x`）。12px だと 375px の幅（使える幅 343px）で2行目の3つが 1px 足りず3行になり、1件目のカードが 52px 下がるので、実測で決めた。
- **角丸**: 意味で4段に分けた。全幅の帯（見出し・調査モードの帯・待ちの1行・下部ナビ）は 0、根拠のラベル 3px、ボタンと入力欄 4px、カード 6px（中のボタンより外の箱を丸く）、方向のチップだけ丸い端（999px）。チップだけ形を変えたのは「選ぶもの（方向）」と「実行するもの（ボタン）」を形で分けるため（3.2 原則2 の見て選ぶ）。
- **影**: 使わない。重なりは線と地の明るさで示す（固定の見出しと下部ナビは 1px の線）。スマホは通学中に使うので（1.1、1.2）、明るい場所で薄い影が見えにくいと境目が分からなくなる（推測で、測っていない）。
- **動き**: 動かすのは3つだけ。(1) ボタンとチップの地の色の切り替え 120ms、(2)「元に戻す」の出入りの不透明度 180ms、(3) 待ちの印の四角3つが 1.2 秒で順に塗られる。位置は動かさない（ずらして出す・拡大する動きは無い）。イージングは cubic-bezier(0.2, 0, 0, 1) で、行き過ぎて戻る動きは使わない。`prefers-reduced-motion: reduce` では切り替えを 0ms にし、待ちの印を止めて塗った状態にする（経過の数字は変わり続ける。動きではなく情報なので）。requirements.md R6-7。
- **状態**: [候補に入れる]は押すとその場で塗りに変わり「候補に入れた」になる。もう一度押すと外れ、「◯◯を外しました [元に戻す]」が5秒出る（3.2 原則4、C04）。確認のダイアログは出さない。

## 5. アイコンの方針

- 既成のアイコン集（禁止リスト P08 に当たるもの）と絵文字とキラキラの印は使わない。AI の機能に特別な印を作らない。AI であることは、文字と破線と黄、根拠のラベルの点線の丸で示す。AI を通る入口の[自分の言葉で探す]（スマホ）には、同じ AI のラベル（点線の丸と「AI」の文字）を付ける〔F4〕。
- 使うのは、意味を持つ線の印9つだけで、見本の中に SVG で手で描いた（12〜16px の格子、線の太さ 1.5〜2px、角は直角）。根拠の種類の3つ（系統図・紙・点線の丸）、「+」と「チェック」（候補の切り替え。選んだチップのチェックも同じ形）、「>」（詳細へ進む・道筋の区切り）、下向きの「>」（学科を変える）、「外に出る」（シラバス原文。大学のサイトが新しいタブで開く）、「三角」（エラー）。
- 印だけのボタンは作らない。どの印にも文字のラベルが並ぶ（下部ナビも文字だけ。行き先が2つなので文字で足りる。5.2）。印は `aria-hidden` にし、読み上げは文字で行う。[自分の言葉で探す]の AI のラベルも `aria-hidden` で、AI に送ることは W5-1 の注意の文で伝える。

## 6. 部品

見本の `final/specimen.html` に全部ある（W1・W11 の画面と、その下の「部品の見本」）。

- **提案カード**（W1・W2・W13・W5-3 で同じ形。C05）: paper の地、rule の 1px の縁、角 6px、内側 12px。上から科目名（17px 太字）、学期・曜限・単位（13px、ink-muted）、「なぜ:」＋1行（15px、2行まで）、根拠のラベル＋「同じ枠にほかに N 科目」、下に[理由と出典 >]（左端。主ボタン＝墨の塗り）と[+ 候補に入れる]（右端。枠のボタン）〔F1〕。AI が出した科目は縁を ink-muted の 1.5px の破線にし、根拠のラベルを黄にする。カードの中にカードは入れない。
- **スマホの見出し**: 高さ 56px、上に固定。左に「コースナビ」（16px 太字）と学科名（13px、ink-muted。押すと学科を変える。調査モードでは押せない）を2段、右に[このAIについて]（文字のボタン）。320px の幅では学科名を省略記号で切り、1行を保つ（読み上げは `aria-label` の全文）。
- **チップ**: 高さ 44px、丸い端、line-ui の 1px の枠、14px、左右の内側 11px。選択中は route の塗り・紙の文字・太字・チェックの印、`aria-pressed="true"`。5個を折り返して並べ、横スクロールにしない（375px で2行。320px では3行に折り返す）。
- **[自分の言葉で探す]（スマホ）**〔F4〕: 方向のチップの下に 16px あけ、幅いっぱいの枠のボタン（高さ 44px、左寄せ）。左に AI のラベル（ai の地・墨の破線の枠・点線の丸・「AI」。根拠のラベルと同じ部品）、続けて「自分の言葉で探す」。丸い端のチップ（方向を選ぶ）と、四角い幅いっぱいのボタン（言葉で探す。AI を通る）を形で分ける。5.1 の構造では方向と並ぶ入口なので、別の区画には分けない。
- **スマホの下部ナビ**: 画面の下に固定、高さ 56px＋端末の安全域。「さがす」「候補」の2つを半分ずつ、文字だけ。選択中は墨の文字・太字・ラベルの下に墨の 3px の線（ナビの下端から 10px）、`aria-current="page"`〔F2〕。「候補」の件数は墨の丸に紙の数字。上の縁は line-ui の 1px の線だけ。スクロールの途中で行がナビの縁で切れるのは固定のナビでは避けられないので、縁に選択の線を重ねない。一覧の最後には下部ナビの高さぶんの余白を取り、最後の行が隠れない。フォーカスやページ内リンクで移った先が見出しと下部ナビの下に隠れないよう、`scroll-padding`（上 64px、下 56px＋安全域＋8px）を指定する（WCAG 2.4.11）。
- **PC の見出し**: 高さ 56px。左から「コースナビ」、学科名（ink-muted）、文字のタブ「さがす」「候補 N」（選択中は下端に墨の 3px の線）、右端に[このAIについて]。調査モードでは見出しの上に帯（3.3）。
- **PC の左右ペイン**（W11）: 左の一覧は幅 392px・地は paper-sunk。上から入力欄と注意（C12）、方向のチップ、自由記述の結果（あれば一覧の先頭）、提案の一覧。一覧の項目は科目名の右に[候補に入れる]、下に「なぜ」と根拠のラベル。右に表示中の項目は墨の 2px の枠と、右のペインを指す墨の三角（`aria-current="true"`）。右の詳細ペインは paper の地で、残りの幅。
- **詳細（W3）の見出しと出典**: 上にたどった道筋（13px。押せる段は下線、C03）。PC の幅 1180px 以上では詳細を2段に分け、どちらの段も道筋のすぐ下から始める〔F5〕。左の段に、科目名（PC 28px・スマホ 22px 太字）、開講・曜限・単位・担当・区分の見出し語（ink-muted）と値、[候補に入れる]、「なぜ出てきたか」（AI の説明は破線の箱、系統図の事実は実線の箱）、「シラバスより（年度）」（カギの角の引用の箱、授業計画の回、概要の抜粋、[シラバス原文を開く（大学のサイト）]）。右の段に「系統図での位置」（緑の縦の線に、先に取っておく枠・この科目の枠（同じ枠の科目）・つながる先の枠を印で並べる）。1280×800 で、つながる先の枠まで最初の表示に入る。1180px より狭いと1段に重ね、仕様の順（見出し、なぜ、シラバス、系統図での位置）に並べる。線は枠どうしを結ぶことと、並びが関係の強さの順でないことを、線の下に書く（7.6、C24）。最後に「この画面で使っていない情報」（7.3）。
- **前後の枠の行**〔F3〕: 枠の名前（15px 太字）の下に、科目名（15px）・学期（13px、ink-muted）・[理由と出典]（右端）を1行に並べ、最後に[この枠の科目をすべて見る（N 科目）]。[理由と出典]は下線の文字のリンク。同じものが縦に並ぶので、枠のボタンにすると重い。押せる範囲は行の高さ（スマホ 44px、PC 32px）。この行には[候補に入れる]を置かない（W3 の注）。
- **待ちの1行**: 3.3 のとおり。スマホは下部ナビのすぐ上、PC は見出しの下。高さ 52px。`role="status"` は状態の文にだけ付ける。
- **調査モードの帯**: 3.3 のとおり。高さ 52px、[使い終わった]は紙の地の枠のボタン。
- **ボタンとリンク**: 3種類のボタンと文字のリンク。主ボタン（墨の塗り・紙の文字。提案カードの[理由と出典]、[探す][見る]）、枠のボタン（紙の地・line-ui の枠・墨の文字。[候補に入れる][やめる][もう一度送る][自分の言葉で探す]）、文字のボタン（下線。[このAIについて][AIの説明を全部読む]）、文字のリンク（下線。前後の枠の行の[理由と出典]、[この枠の科目をすべて見る]、道筋）。[候補に入れる]は枠のボタンで始まり、押すと主ボタンの塗りに変わる切り替え。ポインタを載せると地が一段暗く、押している間は rule の地、押せないときは paper-sunk の地・rule の枠・ink-muted の文字。
- **入力欄**: 高さ 44px、16px、line-ui の枠、角 4px。名前のラベルを上に必ず出す（例文の placeholder をラベルの代わりにしない）。注意（名前や学籍番号は書かない・外部の AI サービスに送られる）は入力欄のすぐ下に 13px で常に出す（W5-1、C12）。範囲外の言葉があったときは枠の色を error に変え、内側に同じ色の 1px の線を足して太く見せる（枠の太さそのものは変えないので、文字の位置がずれない）。下に「データがありません:」で始まる1行を出す。入力した文は消さない（C11）。日本語の変換を確定する Enter では送らない（W5-1、R1-12。実装の決まり）。
- **フォーカスリング**: 3.3 のとおり。`:focus-visible` で、すべての押せる部品に同じ輪。

## 8. 検証の手順と限界

再現（コンペの作業フォルダ `frontend/design` で実行。`F=final`、`R=<リポ>`）:

```sh
uv run python check_banlist.py $R/docs/frontend/DESIGN.md $F/specimen.html
uv run --with pyyaml python check_contrast.py $R/docs/frontend/DESIGN.md
uv run --with fonttools --with brotli python check_font.py $F/fonts/mplus1p-400-ui.woff2 $F/fonts/mplus1p-700-ui.woff2 $F/fonts/mplus1p-400-rest.woff2 $F/fonts/mplus1p-700-rest.woff2
uv run python -I $F/verify/palette.py .            # トークンの OKLCH と hex
uv run python -I $F/verify/color_margin.py .       # 禁止の色との距離
# スクリーンショットと計測（Edge が要る）。shot-375.png・shot-1280.png と verify/shot-320.png・shot-900.png、DM5・PC の右の段・横スクロール・読まれたフォント
uv run --with playwright python -I $F/verify/shoot.py $F/specimen.html $F
uv run --with playwright python -I $F/verify/shoot_phrase.py $F/specimen.html $F/shots   # 文節の改行のあり・なし
uv run --with playwright python -I $F/verify/shoot_parts.py $F/specimen.html $F/verify   # 部品の見本
uv run --with playwright python -I $F/verify/tracking_check.py $F/specimen.html          # 字間と行数
# 書体の見本 14〜16px（README の手順3）。応募作 alpha の fonts の rest を読む（グリフは確定版と同じ）
uv run --with playwright python -I $F/verify/shoot_font_specimen.py . $F/shots
# 書体の比較（2.2。候補の TTF は github.com/google/fonts の ofl/ から取る）
uv run --with fonttools --with brotli --with pillow python -I $F/verify/glyph_distinct.py ux-spec.md "M PLUS 1p=MPLUS1p-Regular.ttf,MPLUS1p-Bold.ttf" …
# 配信ファイルを作り直す（元の TTF は github.com/google/fonts の ofl/mplus1p から取る）。先に shoot.py --chars で字を集める
uv run --with playwright python -I $F/verify/shoot.py $F/specimen.html $F --chars $F/verify/chars.json
uv run --with fonttools --with brotli python -I $F/verify/build_fonts.py MPLUS1p-Regular.ttf MPLUS1p-Bold.ttf $F/specimen.html $F/fonts $F/verify/chars.json
```

- 環境: 2026-11-03、Windows 11 Home、Microsoft Edge 156.0.4314.58（headless、Playwright の chromium の channel=msedge）、uv 0.10.6、fonttools・brotli・pillow・pyyaml・playwright は `uv run --with` で一時的に入れた。
- スクリーンショットは倍率 2（375×812 は 750×1624 画素、1280×800 は 2560×1600 画素）、`prefers-reduced-motion: reduce` で撮った（待ちの印が止まった状態）。375 はスマホの扱い（is_mobile・タッチあり）。
- DM5（375×812）: 1件目のカードは 435.9〜646.7px、下部ナビの上端は 755px で、全体がスクロールなしで見える。なぜの1行目の下端は 524.2px（667px の端末の目安 550px 以内）。応募時は 431.9〜642.7px で、[自分の言葉で探す]の上の間を 4px 広げた分だけ下がった〔F4〕。
- PC の右の段（1280×800）: 「つながる先の枠」は 608.8〜712.5px で、最初の表示に入る〔F5〕。応募時の見本は 798.7〜910.4px（同じ計り方で測り直した値）。
- 横スクロールと部品のはみ出し: 320・375・414・768・1280px で、ページの横幅は画面の幅と同じ、ボタン・チップ・タブ・リンク（文字のリンクを含む）のはみ出しと2行への折り返しは 0（`final/verify/shoot.out.json` の overflow）。320×700 の小さい端末では1件目のカードの下が下部ナビに隠れる（DM5 の条件の外。科目名は見える。なぜの1行目の下端は 600.2px で、応募時の 572.2px より下がった）。
- 書体の見本の撮影（`final/shots/mplus1p-*.png`）は応募作 alpha のときのもの。確定版で作り直した rest も字の集合と形は同じ（作り直しで変わるのは WOFF2 の圧縮のわずかなバイト数だけ）。
- 限界:
  - 書体の比較（2.2）は1倍の画素の差で測った代わりの指標で、1年生に読ませて取り違えを数えた実験ではない。候補は4つだけ。
  - 第2水準の 39% は端末の書体で出る。端末ごとの見え方（iOS・Android の実機）は確かめていない。
