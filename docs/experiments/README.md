# 実験の計画と記録（docs/experiments）

このフォルダには、Course Navigator で行う実験の計画書と、実施した実験の記録を置く。

## 本実験と個人の予備実験の区別

| 種類 | 何か | 置き場所 |
|---|---|---|
| チームの本実験 | 論文で主張する比較。現在の計画は Yuto の Vector vs GraphDB の比較（[`vector-vs-graph-evaluation.md`](https://github.com/cyanosome/course-navigator/blob/test/vector-graph-eval/docs/experiments/vector-vs-graph-evaluation.md)、ブランチ `test/vector-graph-eval`、2026-10-08 作成、計画中） | 計画書はブランチ `test/vector-graph-eval` の同じフォルダ |
| 個人の予備実験 | メンバーが担当タスクの中で行った確認や比較。本実験の結果ではない。本実験の条件や手順を決める材料にする | このフォルダの `YYYY-MM-DD_<名前>.md` |

予備実験の数値を、本実験の結果として引用しない。引用するときは記録へのリンクを付け、実験者・n・実行回数を添える。

## 記録に必ず書くこと

数値だけを共有しない。第三者（チームのメンバー、論文の査読者）が、何をしたのかを理解して同じ手順を再現できるように、次の節を必ず書く。

| 節 | 書くこと |
|---|---|
| 冒頭の要約 | 実験者（本実験か個人の予備実験か）、実施日、一言で何を確かめたか、結論（2〜3行） |
| 1. 目的と問い | なぜ行ったか、何を知りたかったか、依頼元 |
| 2. 仮説 | 事前登録がある場合はそのファイルへのリンクと要点。無い場合は「無い」と書き、期待していたことを書く |
| 3. 実行環境 | 日時（JST）、Docker の構成と版、コミット SHA、LLM のモデル名と版、API の枠（無料・有料）、MCP サーバーの版と設定、温度などの生成設定 |
| 4. データ | DB の中身、質問の出どころと偏り |
| 5. 条件 / 対象 | 各条件の処理の流れ（文と簡単な図）、プロンプトとコードの場所 |
| 6. 手順 | 実行したコマンド、順序、回数、予算の上限、再現のしかた |
| 7. 指標の定義 | 各指標の定義と式、1問分を実際に計算した例 |
| 8. 結果 | 表の直後に各列の意味を書く。条件別の集計、質問別の内訳、外れ値・失敗の説明 |
| 9. 事前登録との照合 | 事前登録から変えたこと（逸脱）とその理由、仮説の判定 |
| 10. 考察 | 何が言えて、何が言えないか |
| 11. 限界 | n、実行回数、データ、モデル、環境の制約 |
| 12. 生データとコードの場所 | リポ内のパスとコミット |
| 付録 | 試行錯誤の経緯。失敗した試行も隠さずに書く |

あわせて守ること:

- 比較の実験は、LLM を使う実行の前に事前登録（条件・指標の式・判定規則・予算）をコミットする。結果を見てから変えたことは「逸脱」として理由と一緒に書く。
- 生データ（1実行1行の記録）と実行条件（コミット・モデル・プロンプトのハッシュなど）をリポに残す。API キーなどの秘密は残さない。
- ファイル名の日付は、その実験に着手した日（JST）。
