## 4. データ

### 4.1 オーナーの依頼（2026-11-04 未明。監査役の書き写し）

- 情報量が多く、認知負荷が高すぎる
- 無駄な見出しがある（「方向」「まず見ておきたい3科目」など）
- 強調は太字でなく色の濃淡で。カードは薄く
- 余白は 4・8 の倍数
- 線アイコン。ハンバーガーメニューやパンくずも検討してよい
- 候補に入れたら一瞬のポップアップ。候補を足していくと時間割が組める
- 「方向」→「興味関心」、「まず見ておきたい」→「おすすめ」など、すぐ分かる言葉に
- 根拠・出典は薄く書いてあればよい
- 大事なのは、授業でやること・単位・対象学年・曜日時限・時間割が組めるか。必修と卒業要件を計算したうえで推薦してほしい
- 担当教員・区分は、データがあれば出す
- 「なぜ出てきたか」は1語か線アイコン

応募作への依頼文では、これを F1〜F11 に分けて渡した。e1・e2 への依頼文は会話の中にしか無い（監査役による）。e3 への依頼文はファイルで残っていて、F1〜F11 と事前登録の基準の全文がある（`entries/e3/prompt-1.txt`〈修正前〉・`prompt-2.txt`〈修正1の後〉・`prompt-3.txt`〈修正2と検証の結果を足した直しの回〉・`amend3.txt`〈修正2の文〉）。e3 向けの前置き（シェルと MCP を使わない、書き込まない、返す形）が付いた版で、e1・e2 に渡した文と一字一句同じかは確かめていない。

UX 仕様 v1.1 の決定のうち、依頼で上書きしたもの: 「おすすめ」と書かない（→書いてよい）、ハンバーガーメニューを使わない（→二次的な項目には使ってよい。主な行き先は常に見えること）、根拠の種類を毎回目立たせる（→薄く）。

## 7. 指標の定義

定義の文（事前登録）と、文で決まらない細部（実装で決めたこと 1〜36）は `measure/README.md`。要点だけ:

- CL1: W1 の最初の表示（ビューポート 0〜812px）に見えている文字の数。空白・改行を除き、書記素で数える。閉じた開閉・hidden 属性・display:none・DOM に無いものは数えない
- CL2: 最初の表示に見えている「強調された要素」の数。直下の文字の font-weight が 600 以上の要素と、地の色が透明でなく（alpha ≥ 0.05）「ほぼ白」（R・G・B すべて 240 以上）でもない要素の和集合。親の地と同じ色の要素は数えない
- CL3: 最初の表示に見えている文字を持つ要素の、(font-size, font-weight, color) の組の種類の数
- RM6: 6画面（W1・W3・W3-open・W4・W4-add は 375×812、W11 は 1280×800）の見えている全要素の margin・padding・row-gap・column-gap の計算後の値（0・auto・normal を除く）のうち、4 の倍数と 8 の倍数の割合。判定は6画面の値を合わせた割合で行う
- BL: J1・J2 の (a)(b)(c) の順位（6つ）の平均を、案の間で順位にしたもの
- 順位: CL1〜CL3 は値が小さいほど上。同じ値は平均順位
- 合計 = CL1 の順位 ＋ CL2 の順位 ＋ CL3 の順位 ＋ 2 × BL の順位（小さいほど良い）

## 10. 考察

### 10.1 e1 はどう認知負荷を下げたか

e1 の redesign.md（0章・1章・5章・6章）と測定の値から:

- **太字ゼロ**: 文字の太さは全部 400 で、太字のフォントのファイルを読み込んでいない。測定でも太さ 600 以上の字は 0（改訂前は 105 字）
- **2色2サイズ**: 強調は墨 #1e2428 と灰 #5c656c の2色、16px と 14px の2サイズだけで作る。W1 の書式の組は 16px 墨・14px 墨・14px 灰の3つ（CL3 = 3）
- **カードの箱をやめて線**: カードの枠・地・影をやめ、行の間の細い線で区切った。W1 に塗りの地を持つ要素が無く（選んだチップと候補に入れた＋は緑の輪だけ）、CL2 = 0
- **必修を時間割に先に入れる**: 学科の必修（見本では3科目5単位）は最初から時間割に灰で入れておき、一覧には出さない。W1 は「1年春の必修 3科目は、時間割に入れてあります」の1行で済ませ、一覧は選ぶ科目（選択と他学部）だけにした
- **メニューに二次項目**: 「このAIについて」「学科を変える」「想定の時点」「時間割を文字でコピー」を右上のメニューに入れ、W1 から外した。主な行き先（さがす・時間割）は下のタブで常に見える
- ほかに: 見出しを0にした。中黒でつないだメタ情報をやめ、曜限と単位を左の列に縦に置いた。［理由と出典］のボタンをやめ、行を押すと詳細に行くようにした。残りの2科目と並びの説明は「ほかに2科目」の中（閉じている間は DOM に無い）

J1 は (a) の理由に、e1（案3）の一覧が「左の列に月2／2単位、右の列に科目名と一行の説明を並べるだけ」で、ボタンも右端の小さな＋で済ませている点を挙げた。J2 も同じ並びを理由に挙げた。CL1 の順（e1 < e2 < e3）は BL の順と同じだった。ただし案は3つだけなので、CL1 が感じ方を表すとまでは言えない。

## 11. 限界

- 各案1回の生成（e3 は直し1回を含む）。同じ依頼で作り直すと、結果は変わりうる
- 審査役は各1回で、案の名前や見せる順を入れ替えた2回目はしていない。e1 はいつも案3（最後）として見せたので、見せる順の効果を分けられない（J1 は1回の中で観点ごとに見直す順を変えたと書いている。J2 への依頼文は画像を案1→案2→案3 の順で並べた）
- 審査は静止画18枚だけで、知らせの動きや操作の流れは見ていない（RM5 は測定役が実際に押して確かめた）
- 見本のデータは架空で、案ごとに科目名・説明文・担当が違う。CL1 は見本の文の長さにも左右される
- 卒業要件のデータが無い（`data-availability.md`）。e1 の W1 の推薦の理由「教養があと4単位（卒業要件）」や、W4 の「上限 24」「卒業に要る単位 13 / 124」は見本の数で、今のデータでは出せない。e1 自身も、データが無い間はこれらを出さないと書いている（redesign.md の8章）。区分もコードしか無いので、「必修を先に時間割に入れる」には区分の対応表が要る
- CL は W1 の最初の表示だけを測った。W3・W4・W11 の情報量は測っていない
- 案が3つだけなので、CL と BL の順が一致したのは偶然かもしれない
- 応募作も審査記録も AI が書いたもので、誤りを含みうる。J1 は e1・e2 と同じ Claude の系統、J2 は e3 と同じ Gemini の系統
- e1・e2 は作業中にデータの調査を読んだが、e3 は読んでいない（5節の条件の差）
- 測定のスクリプトの細部（`measure/README.md` の「実装で決めたこと」）は、定義の文で決まらない部分を測定役が決めたもの
