# [ADR-0009] 最速プロトタイプ検証のための長崎大学データ先行 Ingestion への方針転換

- **ステータス**: 承認済 (Accepted)
- **起票日**: 2026-09-09
- **決定者 / 議論の場**: yuto (@cyanosome), ibuki, akiha (@Akitoshi-Hasegawa) / MTG 0909
- **関連リンク**: `docs/roadmap.md` (Phase 3), `docs/architecture.md`

---

## 1. 背景と課題 (Context & Problem Statement)

- **基盤疎通から「検索アプローチとユーザー体験の検証」へのフェーズ移行**
  - これまで進めてきたコンテナ疎通テスト（Communication Test）およびダミーシードデータによる Agent 疎通（Phase 2）を経て、開発はいよいよ「実際の検索アルゴリズム、推薦の納得感、UI/UX のデザイン方針」を決定する段階へと到達した。
- **データ取り込み（Ingestion）の制約とユーザー期待の早期把握の必要性**
  - データ構築において「シラバスからどの程度の情報が抽出できるのか」という Ingestion 側の技術的制約と、「実際の学生が履修相談において何を求めているのか」というユーザー側の期待値をできるだけ早期に突き合わせ、デザインや機能の方向性を定める必要があった。
- **フルスペックオントロジー（CS2023）導入の先行リスク**
  - 当初の構想通り、最初から ACM/IEEE CS2023 オントロジーへのマッピングを試みると、オントロジー構造の定義と LLM 推論パイプラインの調整に膨大な時間がかかり、実際に動くアプリケーションを学生に触ってもらうまでの期間が大幅に遅延するリスクがあった。

---

## 2. 決定の判断基準 (Decision Drivers)

- **プロトタイプ完成までのリードタイム（最速で動くものを作れるか）**: 抽象的なオントロジー構築に時間を費やす前に、単一大学の閉じたデータで最速でエンドツーエンドの検索アプリを立ち上げられること。
- **シラバスデータの収集・抽出の容易さ**: スクレイピングやテキスト抽出の技術的ハードルが低く、クリーンなデータを速やかに準備できること。
- **テストベッド環境と被験者（学生）の集めやすさ**: 開発メンバーが所属し、リアルな学生ユーザーを対象にしたヒアリングや利用テストを容易に実施できること。
- **実証実験の時期的な即時性**: 履修登録や科目選択が実際に行われる切実なタイミング（履修変更期間など）にテストを実施できること。
- **学部組織のオープン性と教員ヒアリングの可能性**: カリキュラムマップの妥当性について教員へ直接フィードバックを求められる環境であること。

---

## 3. 検討した選択肢 (Considered Options)

1. **選択肢 A: 当初計画通り、CS2023 オントロジーの全マッピングを先行する案**
   - CS2023 の Knowledge Area / Unit を投入し、最初から国際標準オントロジーに各大学のシラバスを対応付ける。
2. **選択肢 B: 駒澤大学などの他メンバー所属大学のシラバスを先行対象とする案**
   - メンバーの身近な大学をターゲットとする。
3. **選択肢 C: 長崎大学 情報データ科学部のカリキュラム・シラバスを先行 Ingestion し、CS2023 マッピングに先んじてプロトタイプ検索アプリを実装する案 【採用】**
   - オントロジーマッピングは一旦保留し、長崎大学 情報データ科学部の実データのみを取り込んで即座に検索アプリと UI を完成させ、学生インタビュー実験を行う。

---

## 4. 決定事項と選定理由 (Decision & Rationale)

**採用**: **選択肢 C: 長崎大学 情報データ科学部データの先行 Ingestion とプロトタイプ実装**

### 長崎大学 情報データ科学部を選定した 5 つの決め手
1. **シラバスデータが PDF で一括公開されており取得が容易**:
   - Web サイトの奥深くに埋もれていたり動的レンダリングを要する大学が多い中、長崎大学 情報データ科学部はシラバスが PDF として整理・公開されており、テキスト抽出および Ingestion のパイプライン構築が極めて容易である。
2. **開発メンバー ibuki 氏の所属とサークルコミュニティの活用**:
   - 開発メンバーの 1 人（ibuki 氏）が長崎大学 情報データ科学部の現役学生であり、学内のプログラミングサークルに所属している。そのため、シラバスや履修ルールに対するドメイン知識が深く、完成したプロトタイプをサークル員や同学部の学生に即座に配布してテスト協力者を集められる強力なテストベッドが存在する。
3. **後期履修登録・変更期間という絶好のタイミング**:
   - ちょうど後期の履修登録・履修変更期間が迫っており、学生が「どの授業を取るべきか」「楽単で妥協すべきか」をリアルに悩んでいる最も切実な時期に、生のユーザーテストとインタビューを実施できる。
4. **他大学（駒澤大学等）の制約回避**:
   - 駒澤大学などのシラバスは詳細が学内 Web サイト等でしか閲覧できず、また組織的な環境が保守的であるため、学外への公開や自由な学生テストの実施に制約や不確実性が大きかった。
5. **新設学部ゆえの教員アクセスの良さ**:
   - 情報データ科学部は近年新設されたばかりの新しい学部であり、カリキュラム・マップの設計意図や教育目標について、学部の教員に直接意見やヒアリングを行える機会が得られる可能性がある。

## 5. 各選択肢の評価 (Pros & Cons)

### 選択肢 A: CS2023 全面先行案
- **メリット (+)**:
  - 最初から全学問分野への展開を見据えた理想的な多層アーキテクチャに準拠できる。
- **デメリット・見送り理由 (-)**:
  - オントロジー投入と自動マッピングの試行錯誤に数週間以上を要し、動くプロトタイプでユーザー検証を行うタイミング（後期の履修登録時期）を完全に逃してしまう。

### 選択肢 B: 駒澤大学等の先行案
- **メリット (+)**:
  - 別のメンバーの身近な環境で検証できる。
- **デメリット・見送り理由 (-)**:
  - シラバスの取得が難しく、学外テストに関する保守的な障壁がある。

### 選択肢 C: 長崎大学先行 Ingestion ＋ プロトタイプ実装 【採用案】
- **メリット (+)**:
  - PDF 入手性、被験者確保（サークル）、実施時期（後期登録）、教員へのアクセスのすべてが揃っている。
  - 実データで動くアプリを最速で手に入れることで、UI/UX や検索ロジックの改善サイクルが爆速化する。
- **デメリット・受容するリスク (-)**:
  - 初期プロトタイプは長崎大学 情報データ科学部に特化した形となるため、CS2023 を介した他大学比較や外部 Web 教材補強の多層化は次期フェーズ（Phase 4）への申し送りとなる。

## 6. 影響と結果 (Consequences)

- **ロードマップへの影響**:
  - `docs/roadmap.md` において、**Phase 3 を「長崎大学データ Ingestion & プロトタイプ検索アプリ実装」**、**Phase 4 を「CS2023 基準オントロジー統合 & Web 教材 Ingestion」** としてフェーズ順序を正式に組み替えた。
  - Phase 3 の実験項目として **「実験 3-4: 学生インタビュー実験（定性評価）」** を新設し、サークル員等を対象としたヒアリング計画を明確化した。
- **実装面のアクション**:
  - ルート直下の `ingestion/`（ADR-0008 で新設）において、長崎大学の PDF シラバスをパースして Neo4j / PostgreSQL へ投入するスクリプトの実装に着手する。
  - フロントエンド側は、長崎大学の学生がストレスなく操作できるよう、チャット UI および前提ツリー表示の微調整を先行する。
