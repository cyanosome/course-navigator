# PX-1 事前登録: 履修系統図なしで LLM は学科の公式の履修順序をどこまで再現できるか

- 位置づけ: 個人の予備実験（実験者 Aki_Ha。チームの本実験ではない）。実行はサブエージェント（Claude Opus 5.5）
- 作成: 2026-11-05（JST）。この文書の SHA-256 と保存日時は `prereg.sha256` に置く。LLM の呼び出しはその後にだけ行う
- 設計の出どころ: 監査役（メインループ）が決めた設計。第1節〜第8節は依頼文の設計をそのまま写したもの。第9節以降が、実行役がデータを見て足したもの（標本の具体値と乱数の種）と、設計の文言を機械的な判定にするための実施の細目

## 1. 問い（設計のまま）

履修系統図（グラフ）なしで、LLM は学科の公式の履修の順序構造をどこまで再現できるか。グラフが LLM の知識に無い情報を持つか（＝知識グラフに接地する意味があるか）。

## 2. 課題（設計のまま）

- 向き課題 O: 異なるグループに属し、グループ間に有向路がある科目ペア (A,B)。「この学科の履修系統で、先に学ぶ（もう一方の土台になる）のはどちらか」を A/B の2択で答えさせる。提示順は半分を入れ替える（種を固定）。
- 検出課題 D: 異なるグループに属する科目ペアで、有向路がある（どちら向きでも）ものと無いものを半々。「この学科の履修系統で、一方がもう一方の土台になる関係があるか」を はい/いいえ で答えさせる。
- 正解はグラフの到達可能性。注意: 線が無いことは「無関係」と同じではない（構成概念の限界として報告に書く）。

## 3. 条件（設計のまま）

- C0: 学科名と科目名だけ
- C1: C0＋授業概要と到達目標（各300字まで）
- C2: C1＋配当年次・学期
- 基準 B-year（LLM なし）: 向き課題で配当年次の早い方を先とする。同じ年次・学期なら種固定のコイン投げ。

## 4. モデル（設計のまま）

agy の `Gemini 3.8 Flash (High)` と `Claude Sonnet 5.5 (Medium)`。各条件2回ずつ。1回の呼び出しに20ペアまでまとめ、JSON だけを返させる。ペアの並びは呼び出しごとに乱順。無効な返答は1回だけ再試行し、それでも無効なら無効として数える。

## 5. 標本（設計のまま）

向き課題 120 ペア（うち 20 組の三つ組〈A→B→C の鎖から3ペア〉と、30 ペアの鏡像〈(A,B) と (B,A) を別の呼び出しに〉を含む）、検出課題 120 ペア（有 60・無 60）。足りなければあるだけ使い、その数を書く。

## 6. 指標（設計のまま）

- 向きの正答率（Wilson の 95% 区間）。条件間の差は同じペアで McNemar 検定（正確検定）
- 検出の balanced accuracy・MCC・「はい」の適合率と再現率
- 反対称の矛盾率 = 鏡像ペアのうち、2つの答えが矛盾する（両方とも先に提示した方を先とする、または両方とも後に提示した方を先とする）割合
- 三つ組の循環率 = 三つ組のうち、3つの答えが循環する（A<B, B<C, C<A）割合
- 実行間の一致（2回の Cohen の κ）、無効率

## 7. 仮説（設計のまま。判定は機械的に）

- H1: C1 の向きの正答率は、2モデルとも 0.90 未満（グラフ無しでは10回に1回以上、順序を取り違える）
- H2: C0 の向きの正答率は、B-year を上回らない（名前だけの LLM は年次の規則より良くない）
- H3: C1 の検出の MCC は 2 モデルとも 0.5 未満で、「はい」の適合率 < 再現率（関係を言いすぎる）
- H4: C0 の反対称の矛盾率か三つ組の循環率が、少なくとも1つのモデルで 0.05 以上（グラフは定義上どちらも 0）
- H5: C2 の向きの正答率は C1 より 0.05 以上高い（LLM は年次の情報に頼る）

判定には2回の平均を使い、各回の値も表に出す。

## 8. 予算（設計のまま）

agy の呼び出しは合計 250 回まで。並列は3本まで。

## 9. データ（LLM を呼ぶ前に確定。実行役が記録）

- 対象: 関西大学 環境都市工学部 エネルギー環境・化学工学科、2026年度
- 履修系統図: `tree_env.pdf`（https://www.kansai-u.ac.jp/ja/assets/pdf/about/outline/faculty/tree_env.pdf、2026-11-05 00:02 JST 取得、SHA-256 `d15522c5…c91d3`）の 6 ページ目を、リポ（origin/main `14f8d570dd954059dd9756c5f9fe3ba1584dbc75`）の `KansaiCurriculumTreeParser` で解析した。グループ 21（うち DP1〜3 の3つは科目を持たない到達目標）、辺 25、非巡回。抽出された辺はリポのテストの期待値 `EXPECTED_25_EDGES` と一致した
- 所属: リポの Transformer はグループの所属科目を手書きの表（`PAGE_6_GROUPS_DEF`）で持つ。PDF の文字の座標と照合し、64 科目は枠と一致、残り 6 科目（共通教養科目の枠、縦書きで文字が分断）は枠の中にあることを確かめた。系統図の科目は 70
- シラバス: 学科の科目一覧（catalog、1029件）を取得し、系統図の科目に当たる詳細ページ 127 件だけを 1.2 秒以上の間隔で取得した。リポの `KansaiSyllabusTransformer` で 127/127 を JSON にした
- 科目の対応: 70 科目のうち 65 は正規化後の科目名の完全一致、2 は「数学を学ぶ（微分積分N・演習N）」が catalog で講義と演習の2科目に分かれていたもの（講義を代表にした）、3 は 2026年度の catalog に無い（グリーンケミストリー、品質管理、エネルギー材料学）。**PX-1 の標本の母集団は、シラバスのある 67 科目**
- 同名で複数クラスあるときの代表は syllabus_id が最小のクラス。配当年次は year_range の最小の年次（どの科目もクラス間で同じ）。学期は全クラスの学期の最頻値（「秋（隔・ク）」は秋、「夏集」は夏期集中）
- 授業概要・到達目標は、空白を1つにまとめてから先頭 300 字で切った

## 10. 標本の具体値と乱数の種（実行役がデータを見て決めたもの）

- 乱数の種: `SEED = 20261105`。用途ごとに `random.Random(f"{SEED}:{用途}")`（用途: triples, mirror_base, swap_triples, d_pos, d_neg, d_order, byear_coin, batch:{課題}:{条件}:{回}）
- 科目の DAG: 科目 x → 科目 y は、x のグループ → y のグループがグループ DAG の辺のとき。同じグループの科目どうしは結ばない。到達可能性はグループ DAG の到達可能性
- 母集団の大きさ（67 科目）: 有向路のある順序対 920、異なるグループの非順序対 2039（有向路あり 920・なし 1119）、直接の辺の鎖 A→B→C 2506
- 向き課題 O（120 項目、異なる非順序対は 90）:
  - 三つ組 20 組 = 60 項目。三つ組は「直接の辺の鎖」A→B→C（A のグループ → B のグループ、B のグループ → C のグループがともに辺）から、どの非順序対も他の項目と重ならないように無作為に選んだ。各組から (A,B)・(B,C)・(A,C)
  - 鏡像 30 組 = 60 項目。有向路のある順序対から、三つ組の対と重ならない 30 組を無作為に選び、(A,B) と (B,A) の2項目にした
  - 提示の入れ替え: 三つ組の 60 項目のうち 30 項目を無作為に入れ替え。鏡像は構成上 30 項目ずつ両向き。合計 60/120 が入れ替え
  - 設計の「120 ペア（うち三つ組と鏡像を含む）」は、120 項目 = 三つ組 60 + 鏡像の元 30 + 鏡像 30 と解釈した
- 検出課題 D（120 項目）: 有向路あり 60（O の 90 組と重ならない 830 組から無作為）、有向路なし 60（異なるグループで有向路のない 1119 組から無作為）。提示順は項目ごとにコイン投げ
- 呼び出しへの分け方: 課題 × 条件 × 回ごとに 120 項目を無作為に並べ、20 項目ずつ 6 回の呼び出しに分ける。鏡像の2項目が同じ呼び出しに入った並びは捨てて並べ直す（三つ組には制約を置かない）。同じ課題・条件・回のプロンプトは2モデルで同一。プロンプトは全部で 72 本（2課題 × 3条件 × 2回 × 6本）、呼び出しは 144 回の予定
- B-year の答え（LLM を使わないので事前に計算済み）: 標本の 120 項目で正答 117（0.975）、同順位のコイン投げ 5 項目（うち 2 項目が不正解）、同順位でない 115 項目のうち不正解は 1（「物理を学ぶ（電磁気学Ⅰ）」1年秋 → 「化学工学量論及び演習」1年春）。H2 の閾値はこの 0.975 になる
- データの性質として LLM の前に分かったこと: 母集団の有向路のある 920 組のすべてで、後の科目の配当年次は先の科目と同じかそれより後（同じ年次 64 組）。系統図の順序は配当年次とほぼ重なる

## 11. 実施の細目（設計の文言を機械的な判定にするための解釈。実行役が足したもの）

- モデルの呼び方: `agy --gemini_dir=<SP>\px\agy_profile --model "<表示名>" --input-format stream-json --output-format stream-json --print-timeout 600s`。標準入力に `{"event":"user","message":{"content":"<プロンプト>"}}` を1行。cwd は空のフォルダ `<SP>\px\agy_ws`。環境変数 ANTHROPIC_API_KEY・GEMINI_API_KEY・GOOGLE_API_KEY を外す。660 秒で打ち切り。useG1Credits は触らない
- 有効な返答: 前後の空白とコードブロックの記号を外し、最初の `{` から最後の `}` までを JSON として読む。`answers` の各要素の `id` が呼び出しの問い番号で、`answer` を NFKC 正規化・前後の空白除去（O は大文字化）した値が O なら `A`/`B`、D なら `はい`/`いいえ`。同じ id に違う答えが複数あれば、その項目は無効
- 再試行: 呼び出しの返答が無効（JSON が読めない、無効な項目が1つでもある、agy の失敗・時間切れ・空の応答）なら、同じプロンプトで1回だけ呼び直す。項目ごとに、1回目で有効ならその答え、1回目で無効なら再試行の答え（有効なら）、どちらも無効なら無効
- 予算: smoke（各モデル1回、架空の科目の問い。実験の項目は使わない）を含めて agy の起動を数え、250 回に達したら残りの呼び出しはしない（その項目は無効）。実行の順は 1回目の全部 → 2回目の全部
- 正答率の分母は有効な項目（無効率は別に出す）。無効を不正解に数えた正答率も参考に出す
- 2回の平均 = 各回の値の算術平均。Wilson の区間は各回について出す
- McNemar: 同じモデル・同じ回で、両方の条件で有効な項目の正誤の対で正確検定（両側）。C0–C1、C1–C2、C0–C2、各条件–B-year。仮説の判定には使わない
- κ: 同じモデル・条件・課題の 1回目と 2回目で、両方で有効な項目。O は「正解したか」、D は答え（はい/いいえ）を符号にする
- 反対称の矛盾率の分母は、2項目とも有効な鏡像の組。三つ組の循環率の分母は、3項目とも有効な組。循環は向きを問わない（A<B, B<C, C<A と、その逆回り）
- MCC は分母が 0 のとき 0 とし、その旨を表に書く。適合率は「はい」が 0 件のとき未定義
- 仮説の判定: H1・H3 は設計どおり2モデルとも。H2・H5 は主語にモデルの指定が無いので「2モデルとも」とする（各モデルの値も出す）。H4 は設計どおり少なくとも1モデル
